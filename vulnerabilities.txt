TrollNet - vulnerabilities.txt
==============================

STATUS: INTENTIONALLY VULNERABLE TRAINING BUILD
This repository is a laboratory, not a secure application. Every issue below was added
on purpose so players can find and exploit it. Keep it on 127.0.0.1 or a disposable VM.
Do not deploy it, expose it to the internet, or copy these patterns into real software.

2. HOW TO FIND THEM
-------------------

A. Search for the marker (the intended way):

    grep -rn --exclude-dir=bin --exclude-dir=obj --exclude-dir=node_modules \
        --exclude-dir=dist "VULN-SPOT" src frontend/src frontend/nginx.conf \
        docker-compose.yml .env.example

B. Count all markers / count per class:

    grep -rho --exclude-dir=bin --exclude-dir=obj --exclude-dir=node_modules \
        --exclude-dir=dist "VULN-SPOT #[0-9][0-9]" src frontend/src \
        frontend/nginx.conf docker-compose.yml .env.example | wc -l

    grep -rho --exclude-dir=bin --exclude-dir=obj --exclude-dir=node_modules \
        --exclude-dir=dist "VULN-SPOT #[0-9][0-9]" src frontend/src \
        frontend/nginx.conf docker-compose.yml .env.example | sort | uniq -c

C. Search in your IDE for "VULN-SPOT". Each comment names the CWE, shows a way to try
   the exploit, and states the fix.

D. Find them by code smell without using the markers:

    #01  FromSqlRaw with an interpolated string
    #02  dangerouslySetInnerHTML={{ __html: ... }}
    #03  DELETE endpoints with no CanModify(...) call
    #04  CreatePostRequest with AuthorId / IsTrending / CreatedAt fields
    #05  "trollnet.token" cookie + SetIsOriginAllowed(_ => true)
    #06  AddHttpClient() + POST /api/link-preview
    #07  Path.Combine(AppContext.BaseDirectory, name) with no containment check
    #08  MapGroup("/internal/posts") with no RequireInternalApiKey()
    #09  expected == provided / string equality on secrets
    #10  "No account with username" vs "Wrong password"
    #11  MapPost("/login") and /submit without RequireRateLimiting(...)
    #12  SHA256.HashData(...)
    #13  ValidateIssuerSigningKey = false / RequireSignedTokens = false
    #14  objective.IsCompleted = true followed by SaveChangesAsync (no conditional UPDATE)
    #15  ObjectiveDto(..., string Flag) exposed by GET /api/objectives
    #16  literal passwords/secrets in docker-compose.yml
    #17  KnownIPNetworks.Add(0.0.0.0/0) + $proxy_add_x_forwarded_for
    #18  UseDeveloperExceptionPage()
    #19  localStorage.getItem('trollnet.token')
    #20  frame-ancestors * and no X-Frame-Options


3. HOW TO TRY THEM (locally)
----------------------------

Start the lab:

    docker compose up --build

Open http://localhost:8080. The UI creates a guest player automatically.
Reset the database and containers when you want a clean game:

    docker compose down -v

Useful tools: browser DevTools (Network tab), curl, Burp Suite / OWASP ZAP.
Get a token for authenticated calls:

    curl -s -X POST http://localhost:8080/api/auth/guest | jq -r .token

Use it either as "Authorization: Bearer <token>" or as "Cookie: trollnet.token=<token>".

5. AUTOMATED PRESENTATION SCRIPT
-------------------------------

The same explanations are built into the browser UI: open the Tips tab, or click
"Stuck? Open the training tips" / "Need a hint? (#NN)" on the Objectives screen. Tips can be
searched by number, name, CWE or keyword. Each objective carries a tipId; all current
templates point to #15 because that is the vulnerability that exposes every objective
flag. The leaked flag is blurred by default with a Reveal button, but the blur is only
cosmetic: the value remains in the DOM and the anonymous API response.

Because objectives now have a TipId column, reset an existing lab with
"docker compose down -v" after updating.

scripts/demo_vulnerabilities.py does the jobs from this document, plus explanations:

    python3 scripts/demo_vulnerabilities.py --scan              # find/verify all markers
    python3 scripts/demo_vulnerabilities.py --tips              # plain tips for all 20
    python3 scripts/demo_vulnerabilities.py --tip 7             # one tip (#07 or 7)
    python3 scripts/demo_vulnerabilities.py --demo --explain    # tip, then evidence, per class
    python3 scripts/demo_vulnerabilities.py --all --locations   # scan + demo with file:line output

The same tips are saved in vulnerability_tips.txt for printing. RUNTIME means the script
observed the issue over HTTP; STATIC means it proved it from the source (timing/hashing
checks are noisy or read-only). Start the stack first with "docker compose up --build"
for --demo/--all; --scan/--tips work without it. The script reports PASS/FAIL for all 20
classes, prints evidence, and ends with a summary. A clean run shows "20/20" checks
passed. It is local-only and creates temporary posts/users; reset with
"docker compose down -v" afterwards.

You can also run the same flags in Docker with the one-shot "demo" profile. The helper
container uses TROLLNET_BASE_URL=http://frontend:8080, so no --base-url is needed:

    docker compose --profile demo run --rm --no-deps demo --scan
    docker compose --profile demo run --rm --no-deps demo --tips
    docker compose up -d
    docker compose --profile demo run --rm demo --demo --explain
    docker compose --profile demo run --rm demo --all --locations


6. RULES
--------

- Run only on your own machine or an isolated training VM.
- Do not point these endpoints at systems you do not own.
- Reset with "docker compose down -v" between exercises if state interferes.
- Every marker comment includes the fix; read it after exploiting the issue.
